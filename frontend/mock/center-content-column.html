怎么用：拖上面的宽度滑杆，等于拖窗口边框；框内的媒体查询、vw、以及外壳的居中都按框宽算，与真窗口一字不差。 三案在 1280px 以上完全一样（都居中），在 1088px 以下也完全一样（都退回现状）—— 差别只活在 1088–1280 这一段。所以：把滑杆拖到 1200 附近，四案逐个点（就是下面表里那三行）； 再拖着滑杆来回跨过 1280，看甲案那一下横跳、丙案怎么滑过来、乙案怎么把注文栏顶出屏。

要看的三样：正文栏中心与页心线是否重合；注文栏左沿离窗口左边还有多少；页脚那条横线是不是还贴着正文栏。 想拿真窗口试也行：直接开 center-content-column-frame.html（它就是标本本身），或用 F12 里的设备工具栏（Ctrl+Shift+M）输入宽度。

三案的分别 —— 只差「不够宽的时候怎么办」

甲 · 断点左移（已选定并落地，2026-10-10）：@media (min-width: 80rem) { .row { translate: calc((var(--margin) + var(--gutter)) / -2); } }。 1280px 起正文居中、注文栏左移；更窄的窗口一字不动（与现状同）。一条规则、零副作用； 代价是跨过 1280px 时正文横跳 128px。把滑杆拖到 1280px 两侧看这一下。

乙 · 全宽左移：同一条左移，不设断点。用它看窄窗口的代价 —— 视口窄于 1248px 起注文栏左沿出屏被切， 1088px 以下连正文栏本身也开始跟着偏左。

丙 · 连续左移：左移量取「半栏」与「页边富余」的较小者，视口越宽移得越多，77rem 处正好移满； 67rem 以下与现状完全一致。没有跳变，代价是 67–77rem 这一段正文只是偏得少一点、并未居中。
