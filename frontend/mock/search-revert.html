三条规矩

① 没有搜索，末尾什么都不加。前面点「现状」那一栏里没有这一项了——这一页 就是定稿，不摆改之前的对照。想看改之前的样子，线上那一页还在：在搜索框里打一个词、回车、 再点掉右端那颗 ✕，列表照旧只给那一条，页上也没有别的路。

② 有搜索、结果非空，末尾一枚去路。它站在正文栏左沿，与条目标题、摘要同一条 起笔线，横线（.ruled）也从那儿起——这与空结果那一格的「查看全部文章」是一个 位置、一个长相（都是 .pager-btn）。排在分页那一行的下面： 末条之后第一件能做的事是留在这一批里继续走（下一页），走出去（撤掉这次搜索）排在它后面。 两条去路各自有横线隔着，仍读得开；代价是它离内容远了一格、落进页脚上沿那一带。 （2026-10-16 改定，原先在分页上面；摆法与量测见稿样 foot-order-final.html。）

③ 有搜索、结果为空，那一格里两枚并排。空结果那一格自带一条出路，所以这一枚 不再单占一行——两枚同在一行里：「返回」（撤词、留分类）与 「查看全部文章」（撤词也撤分类，就是现在那一格里的 reset()）。 顺序按你说的：返回那一枚在前。分类停在「全部」时这两枚是同一件事（都撤词、都留在全部）， 只留一枚。

两枚怎么排的：它们装在一层 .notice-acts 里。.notice 自己那条 .notice button, .notice .pager-btn { margin-top: 1.4rem } （styles.css:459）得让给这一层——不然两枚各带一份 1.4rem，第二枚就不在同一行了。

那一枚写什么

定下的（2026-10-16）：写「返回」。第二栏可以切到另一句看对照，两边的落法一样。 这一栏就是定稿的样子。

没取的那一句——「查看全部后端文章」（说要去的地方，分类名跟着走）。它当年 好在：这个位置在列表末尾，读者站在这儿问的是「还有别的吗」，说会看到什么 比说会撤掉什么更直接；而且它说的那句话在筛了分类时是真话（点下去留下的 就是那个分类的几篇，写「全部文章」才是假话）。

「返回」的代价，留着备查：① 这一页里「上一页」已经占住了「退」这个意思 （ArticleList.vue:164），两枚并排时读起来有点撞；② 它不是浏览器的后退，是本页内 的一次筛选变更。真要收这两条时，改的是这一枚的文案，别处一行不动。

顺带一句：定了「返回」之后，那一句里的分类名不用拼了——catName 那个 computed 不必写（空结果那一格里第二枚是固定句「查看全部文章」）。

三档数量各是什么样

0 篇（空库）——第一栏点它。这时没有搜索，所以末尾什么都不加（规矩①）； 列表里那一格是原来就有的样子：「还没有找到这样的文章」加一枚「查看全部文章」。 顺带记一笔：库是空的时候那一枚点下去不发生什么（本来就是全部、也没有词），要不要给空库另写 一句话，是另一件事，这一轮没动它。

6 篇（一页装得下）——第一栏点它。分页那一行不出现。搜一个词：搜到就末尾一枚， 搜不到就那一格两枚。

14 篇（多于每页 6 篇）——第一栏点它。分页那行出现（上一页 / 1 / 3 / 下一页， 真的能翻，地址里带 ?page=）。这时搜一个词，末尾那一枚正好落在分页行与页脚 之间，两条去路上下相邻、各有一条横线隔着——就是上面规矩②说的那件事。

翻页时它跟着走：翻到第 2 页，那一枚照旧在最后一条底下（它是列表末尾，不是 第一页末尾）；从第 2 页点它，回到这个分类的第 1 页、词撤掉。

落到产品里改哪几行

甲（手势）——ArticleList.vue 的输入框上加一条 @input， 函数只有一句：

if (search.value.trim() === '' && query.q) go({ q: '', page: 1 });

条件是「本来就有词」：没有就别动，否则每次清空都往历史里推一条空记录。分类不进这次变更 （go 只并进 { q: '', page: 1 }，其余照旧）。

②末尾那一枚——在 <nav class="pager"> 之后插一个 .row（2026-10-16 从分页上面挪下来，见 foot-order-final.html）：

<div v-if="query.q && !loading && !error && items.length" class="archive-foot row ruled">
  <div class="archive-foot-main">
    <button class="pager-btn" type="button" @click="clearSearch">返回</button>
  </div>
</div>

clearSearch() 是 reset() 收窄成一句：search.value = '' （免得框里留着旧词）、go({ q: '', page: 1 })、focusHeading()——这枚 按钮点完就没了，焦点不能悬在空处。分类不进这次变更。

条件里的 items.length 不是 pagination.total：页码超出时接口不夹取， 这一页会是空的（总数却大于 0），那时空结果那一格正在摆它自己的两枚——用总数当条件会两处 同时站出来，就是你图 2 那个毛病。用「这一页有条目」两处互斥。

styles.css 两条：.archive-foot { margin-top: 1.75rem }（与 .pager 同值）与 .archive-foot-main { grid-column: 2 }（站进正文栏）； 窄屏再加一条：44rem 那一档 .row 只剩一列（styles.css:1057）， .archive-foot-main 要跟着 .archive-main、 .archive-tools-main 一起收回 grid-column: 1（添进 :1058 那一行名单）。用 .pager-btn 那枚现成的字，不必新写样式。

③空结果那一格——把现在那一枚换成一排：

<div class="notice-acts">
  <button v-if="query.q && query.category !== ALL" class="pager-btn" @click="clearSearch">返回</button>
  <button class="pager-btn" @click="reset">查看全部文章</button>
</div>

第一条 v-if 里两个条件各管一头：query.category !== ALL 是「分类停在 全部时只留一枚」——那时两枚是同一件事（都撤词、都留在全部）；query.q 是「本来 就没搜，就没有词可撤」——没有搜索时那两枚摆不出两件不同的事。styles.css 再加两条：.notice-acts { margin-top: 1.4rem; display: flex; flex-wrap: wrap; align-items: baseline; gap: .75rem 1.5rem } 与 .notice-acts .pager-btn { margin-top: 0 }——那 1.4rem 是 styles.css:459 给 .notice 里每一枚按钮的，得让给这一层。

没跟着改的：①出错那一格（暂时无法读取文章）只有「重新加载」一枚 ——取数没成功，读者要先把数据拿到手，去路先不摆；②加载骨架里什么都不摆。

两处搜索框：写作台列表页（AdminArticleListView.vue）也是同一个毛病 （清了框、列表还筛着）。甲照抄，只把条件换成它本地的 query.q（那边不进地址）； ②③也照抄——它那儿同样有 .entries 与 .pager （:202、:265），条件里再多一条 state === 'ready' （那边的加载态是这么叫的）。「撤词」那一头只撤 q：那边的状态筛选（草稿／已发布） 与分类是同一个东西的两副样子，都照旧留着。
