甲：一条规则

  • 规则：@media (min-width: 80rem) { .row, .shell > .md, .shell > .banner { translate: calc((var(--margin) + var(--gutter)) / -2) } } ——整块左移 8rem（半个两栏），正文栏的中线落到页心上。落地时原文进 src/styles.css，就写在 .row 那条骨架规则的近旁；这一页头上那一段就是它。
  • 为什么是 translate 不是负 margin：页脚是 .row.shell 一体的（靠 margin-inline: auto 居中），负 margin-left 会顶掉自动居中、把整块推出视口； translate 只挪画出来的位置，不动排版——粘性、锚点让位、断行都还是老样子。
  • 门槛 80rem 的来路：左移的钱只能从页边拿，8rem ≤ (视口 − 67rem) / 2 + 3rem，解出视口 ≥ 77rem；甲案取 80rem（1280px）留一口气。比它窄的窗口一字不动。
  • 两条顺带：.md（编辑台的 Markdown 一栏）与写作-分类页顶上的 .banner 不是 .row，但今天与整块共用同一条左沿，必须一起走——不然编辑台上正文框差出整整 8rem。 带 .shell 直接子代前缀，是为了避开长在 .row 里的那些 .banner（登录、注册、账号、编辑台里都有），免得移两回。顶层的那种这一册里没有摆（它是「这一下没做成」的错误态）。

不动

  • 所有尺寸：--margin 13rem、--gutter 3rem、--measure 45rem、字号与行距、两道窄屏断点（56rem / 44rem，都在 80rem 之下，与甲案无交集）。
  • 报头：它是站的门面，宽度单算一档（--site-shell 105rem），本来就不与内容左沿对齐——现状即如此，甲案没碰它。页脚是 .row，跟着走。
  • .ruled 那条线仍从正文栏左沿起；页脚那条线左右各宽 3rem，是页脚自身那 3rem 内边距造成的（既有小账，甲案不动）。
  • 窄屏：80rem 以下，甲案的页面与现状逐像素相同。

看的时候可以留意

  • 跨过 1280px 那一下：正文横跳 128px 是甲案的已知代价（选甲时把乙、丙的同档读数都比过）。
  • 窗口越宽，注文栏左边余得越多；1280px 时余量最小（约 17px）——那是最紧的一档。
  • 用上面的开关切两态对照：每一页的整块应当整整平移 8rem，报头不动，页脚跟着走。
  • 这一页里报头、编辑台的切换行、保存条不再粘住：十四个整页叠起来，粘住的盒子会一路盖住下文。粘性另有 sticky-masthead.html 与 editor-sticky.html 把关。
  • 演示数据取自 mocks/articles.js；写作台列表只摆四行，真实一页十行。

怎么验

  • 逐页量（CDP 探针 center-content-column-pages-probe.mjs）：逐页读正文栏左沿与页心，1512 / 1280 / 1200 三档 × 开关两态—— 1512 与 1280 下两态互差应为 128px（min-width 含等号，1280 正是规则生效的最紧一档），1200 下应为 0；同时核对滚动宽恒等于 clientWidth（不出横向滚动条），并逐页出整页图。
