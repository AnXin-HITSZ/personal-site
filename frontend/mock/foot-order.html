三案各读成什么

甲（现状）：去路紧贴内容，分页留在页面级的位置。读完最后一条，紧接着的 下一段就是去路，不用先过一眼分页、再做一次「要不要翻页」的决定；分页是常驻控件 （不搜索时也在），挨着页脚正合适——页面级的东西归页面级那一带。 代价就是你在截图里看到的那一眼：末尾连着两条各只装一枚字的窄带子。

乙：从「留在这一批」到「离开这一批」，递进是对的。翻页还在集合里，去路在 集合外，先里后外，逻辑顺。代价有两处：① 去路掉进分页与页脚之间那一带，一枚小字按钮 贴着页脚，读起来像页面级的「回上一页」，而它实际撤的是这次搜索；② 读完最后一条要先 看分页、决定不翻，才轮到去路。

丙：一条带子装两件事。去路贴正文栏左沿（与条目标题同一条起笔线， .ruled 的横线也从那儿起），页码仍钉在栏心中线——两个位置都保住，碎感没有了。 它就是甲去掉那条多余横线的样子。代价写在下面「丙要动产品哪几行」里。

丙要动产品哪几行

分页那三枚现在是按格位认人的（styles.css:505-506）：

.pager-nav > .pager-btn:first-child { justify-self: end; }
.pager-nav > .pager-btn:last-child { justify-self: start; }

丙要在第一格里放两样东西（返回贴左、上一页贴右），按格位写就认不出谁是谁了——「返回」 也是 :first-child，会被推到那一格的右缘、与「上一页」叠在一起（第一版稿样 就是这么错的，探针当场量出来 Δ −42px）。所以这几条改成按名写 （.pager-prev / .pager-next / 新的 .pager-back）， 两个模板一起补类名。写作台列表页那两个按钮本来就有类名，公开列表页那两个没有，要添。

还有一处同一条改动要带上：「少动的人」那一段（styles.css:1157） 也列着同样两条按格位的选择器，改按名写时一起改——不然那两只手的过渡会在关掉动画的人 那里留着。

窄屏要顺手定一件事：窄屏（≤44rem）分页本来就不止一行——页码单独占一行居中， 两只手在它下面各守一边（styles.css:1139-1145）。三格并排都挤不下，更没有地方 让「返回」与「上一页」同居一格。这一页里丙在那一档多给「返回」一行、放在最上面（见上面 那条 media 规则），整条带子变成三行。另一种做法是丙只在宽屏生效，窄屏退回甲 （返回单占一条带子，在分页之上，与今天一样）。这一条不定，丙在手机上就是另一副面孔。

这一条与那三条规矩的关系

取乙或丙，改的是 search-revert.html 规矩②里的半句话——「它排在分页那一行的 上面」。规矩①（没搜索什么都不加）与规矩③（空结果那一格里两枚并排）一个字都不动： 那一格是自带去路的内容块，和分页那一行本来就不挨着。

写作台列表页（AdminArticleListView.vue）是同一套结构，定了哪一案两处一起走， 不留两样。这一页只摆公开列表页：那两处的差别只有栏里的字，档位一样。

产品代码（ArticleList.vue / AdminArticleListView.vue / styles.css）在这一页定下来之前一行不动。你说哪一案，我再落。
