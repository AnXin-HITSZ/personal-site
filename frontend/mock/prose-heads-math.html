Markdown 正文现在有两处难看。一、标题分不出级：三级标题 17px/600，正文却是 18px——三级比正文还小一号， 和 加粗 更是同一个字号同一个字重；四级以下没有规则，吃浏览器默认。二、LaTeX 公式不渲染： $x \to 0$、$$…$$ 原样当字显示。每节先放现状，再放几个走法，你圈一个。

看稿注意：现状两格吃产品 styles.css 原样，一个字都没改；三个走法的规则都写在下面 <style> 里，选定后原样移植。公式一节用本机 node_modules 里的 KaTeX（0.19.0）现画，看到的就是接上去之后的字形； 若公式退回了原文的样子，是这台机器没装 katex，跑一句 npm i --no-save katex 即可。

一、标题层级

三个走法挑一个。＊结论（选定）：甲 宋体一脉。

现状（不动的话）

三级 17px/600：比正文（18px）小、和加粗同款；四级起吃浏览器默认——四级 18px 粗体就是加粗本身，五级六级越缩越小、还各带各的下边距。这一格原样来自产品规则，不用找差异。

现状

一级标题：正文里少见，和二级同档

JWT 由三段 base64url 拼成：头部说明这个令牌怎么被验证，载荷放声明，签名把前两段连起来做一次 MAC 或 RSA 签名。

二级标题：签名的两半

验证分两步：先验签名，再验声明。签名对了但声明过期，令牌照样不能用——这两步大多数实现都放在同一个中间件里，顺序不能反。

三级标题：HMAC 还是 RSA

对称密钥算得快，代价是验证方也能签发；非对称的一把钥匙只签不验。本站自己签、自己验，没有第三方验证方，所以用 HMAC。

对照一行：整句加粗之后是这个样子，请和上面的三级标题并排比一比，分不出来就说明三级该改。

四级标题：密钥轮换

换密钥那天，旧令牌还得认——验证端同时认新旧两把钥匙，等最长的过期时间过去，旧钥匙才能下线。

二、公式（LaTeX）

地基已定：KaTeX 在浏览器里渲染，$…$ 行内、$$…$$ 独立成行；服务端不动，依赖与接线见页末。要挑的只是独立成行的公式往哪站。＊结论（选定）：甲 居中——已落地（styles.css 的 .katex-block 与 src/markdown.js）。

现状（不动的话）

渲染器不认识公式语法，美元符号和记号跟正文一样是字。文章详情页、写作台校样、QA-Agent 项目页，三处一并如此。

现状

原文里写「当 $x \to 0$ 时，$\frac{\sin x}{x} \to 1$」，页面上看到的就是这样：美元符号、反斜杠，一个不少，全是普通文字。

独立成行的公式也同样是字。原文写：$$ \int_{-\infty}^{+\infty} e^{-x^2} \, dx = \sqrt{\pi} $$，这一串和上一段没有任何分别。

甲 居中

行内公式跟着正文走，不抬不缩；独立成行的公式居中——像印在行间。比正文栏宽的公式整块可以左右拖看，不会撑破版心、也不裁字。

甲 居中

快速排序的平均时间是 O(n log n)，最坏是 O(n²)——基准每次都取到边上那个元素时，递归树退化成一条链，比较次数与 n(n+1)/2 同阶；平时定误差项写 ε，增长阶写 Θ(log n)。

两个常用展开写成一排：

\begin{aligned} (a+b)^2 = a^2 + 2ab + b^2 \\ (a-b)^2 = a^2 - 2ab + b^2 \end{aligned}

矩阵乘法也照常：

(a b / c d)(x y) = (ax+by / cx+dy)

超出正文栏的公式（这个有意写长），整块左右拖：

P(A|B) = P(B|A)P(A) / P(B) = …

公式后面接一段话，用来看独立公式与前后文的距离。写错时的样子（下面少一个右花括号），KaTeX 把它原地染成印色亮出来，保存前就能看见，改对即恢复：

\frac{1}{2

落地要动的东西（选定后）

  • 依赖加一个 katex：katex.min.js 273KB（gzip 约 75KB）、katex.min.css 25KB；字体是十几支 woff2，用一个下一支。
  • 三处 new MarkdownIt() 收进一个 src/markdown.js（文章详情、写作台校样、QA-Agent 项目页共用），统一挂上公式：$…$ 行内、$$…$$ 独立成行。
  • styles.css 正文一节加两组规则：标题层级一组（按选定案）；公式一组——KaTeX 自带的上下边距去掉、超宽可横滚、写错的公式染印色（KaTeX 的 errorColor 选项，不用默认纯红）。
  • 服务端、数据库、接口都不动：库里存的是原文，渲染在浏览器里做。
